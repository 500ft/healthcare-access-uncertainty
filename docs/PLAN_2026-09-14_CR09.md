## Ladder walk and algorithm contract

Reuse `label_candidates` and the current acceptance loop. Route only accepted
components. Keep NumPy/SciPy as the core dependencies; do not implement another
shortest-path solver, add a graph framework, or expand the `full` extra.

Proposed private helper in `analysis/catanroads/extract.py`:
`_component_path_px(mask: np.ndarray) -> list[list[float]]`. `mask` is the tight
boolean crop of one accepted connected component. The helper returns crop-local
`[x, y]` pixel centers; the caller adds the crop origin once.

1. Pad the crop with one background pixel on every side before computing
   `scipy.ndimage.distance_transform_edt`; remove the padding for node values.
   This also defines behavior at image borders. EDT measures distance to the
   component background, not physical road width.
2. Give foreground pixels row-major node IDs. Connect every 8-neighbor foreground
   pair, including diagonal-only contacts, matching existing label connectivity.
   No background nodes or gap bridging. Store a symmetric sparse CSR graph;
   there are at most eight directed neighbor entries per node.
3. Select endpoint candidates on the **geometric** graph, with edge length
   `ell = hypot(dx, dy)` (1 or sqrt(2)). Start at the lowest node ID, select the
   farthest reachable node A, then select the farthest from A as B. Distance ties
   within `rtol=1e-12, atol=1e-12` choose the lowest node ID. This is a two-sweep
   heuristic, not an exact diameter algorithm for general graphs.
4. Between A and B, route using symmetric positive costs
   `w(u,v) = ell(u,v) * (1 / edt(u) + 1 / edt(v)) / 2`.
   Endpoint selection uses geometric distance so thin pixels' larger interior
   costs do not themselves define what “farthest” means. The fixed cost is a
   hypothesis to test, not a tunable parameter sweep in CR-09.
5. Use single-source `scipy.sparse.csgraph.dijkstra(..., indices=source)` for each
   sweep and the weighted route. Never omit `indices`: no all-pairs matrices.
   Reconstruct from weighted distance labels to the target: choose the lowest-ID
   neighbor satisfying `d[current] ≈ w + d[neighbor]` with the tolerance above
   and strictly decreasing distance. This makes equal-cost choices explicit
   instead of relying on a version-specific predecessor tie. Orient the final
   path with the lower endpoint node ID first.
6. Keep every vertex, with no repeated consecutive vertices. Every step is an
   8-neighbor step in the same component. No four-pixel sampling, smoothing,
   skeleton pruning, or Douglas–Peucker in this change. State the known ceiling
   in a `ponytail:` comment: one route cannot encode branches or closed loops;
   use separately scoped topology extraction when that is needed.

Handle disconnected/empty masks, an unreachable endpoint, or an invalid
predecessor chain as an explicit `ValueError`. These violate the accepted-component
contract; do not return the old chord or silently drop a candidate. Tests exercise
the helper's narrow contract without promising to repair arbitrary malformed rasters.

The design uses O(B + V + E) storage for crop area B and component graph V/E,
and a fixed number of single-source searches. Record measured synthetic runtime
and largest component size; do not claim full-scene scalability from 256-pixel tiles.

API basis: SciPy's [Dijkstra documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csgraph.dijkstra.html)
defines single-source indices, warns about asymmetric weights with undirected
graphs, and notes version-dependent choices among equal solutions. Its
[EDT documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.distance_transform_edt.html)
defines distance to zero-valued background. The padding, symmetric cost, endpoint
heuristic, and tie policy above are this plan's design choices, not SciPy guarantees.

## Data and consumer contract

| Field or consumer | Required behavior |
| --- | --- |
| `path_px` | New field on every newly extracted candidate; ordered finite `[x, y]` pairs, at least two distinct vertices, in global raster coordinates |

Validate numeric finite N×2 geometry, N≥2, and no consecutive duplicate points. Malformed present paths raise `ValueError`, including `None`, empty, NaN/Inf and wrong shape |
| `to_geojson` | Emit the selected path as one LineString; apply the supplied transform to **every** vertex. Omit both coordinate arrays from properties; retain scalar attributes. Endpoint-only legacy dictionaries continue to work |

| Demo | Plot the same selected coordinates; caption describes measured synthetic behavior and avoids implying branch recovery or real-road validation |

The current scoring band is **two iterations of four-neighbor dilation**, an L1
pixel tolerance, not a Euclidean two-pixel disk. Preserve that exact convention,
`tol_px=2`, and the existing `line_ok` cutoff of recall/precision ≥0.5. Do not
change a metric while comparing the old chord and new path.

## Amendment A — endpoint selection (adopted by the owner 2026-09-16)

Replaces contract step 3. The two geometric sweeps still locate the two ends. At each end,
the endpoint is the pixel **within one half-width (`max(edt)`) of that end's farthest
pixel** that is closest to the component's major axis (PCA of the component pixels, the same
axis as `endpoints_px`), then the farthest of those, then the lowest node ID. Everything
else (padding, symmetric cost, single-source searches, canonical reconstruction, every
vertex kept, `ValueError` contract) is unchanged. Re-measured T08 with the frozen scorer and
thresholds: wide 1.00 / 1.00, low_snr 0.99 / 1.00, tight_curve 1.00 / 1.00, demo 0.93 / 1.00,
faint 0.93 / 1.00, gradient 1.00 / 0.90 — A2 and A3 pass; the wide-strip and true U-turn
fixtures both keep their tips. Two intermediate rules tried during the amendment are
disclosed in the evidence as development data.
